# テスト勉強 進捗管理ツール(GAS + HTML Service)

Googleスプレッドシートをデータベースとして使う、テスト勉強の進捗管理Webアプリです。
GASのWeb Appとしてデプロイすると、PC・スマホどちらからでも同じURLで使えます。

## 機能

- **次の試験カウンター**:最も近い試験日を「次の試験:数学・英語 あと3日」の形式で表示(同日の複数科目はまとめて表示、過ぎた試験は自動除外)
- **全体進捗ゲージ**:全タスクの平均進捗率をリング表示
- **科目別カード**:試験日バッジ+個別カウントダウン、進捗バー、タスク数(◯件中◯件完了)。タップでタスク一覧を展開
- **タスク管理**:進捗スライダー(その場で保存)、期限日、メモ、追加・削除。すべてリロードなしで反映
- **期限アラート**:期限まで3日以内 or 期限切れの未完了タスクを自動抽出して警告
- **科目の管理**:モーダルから科目の追加・削除・試験日の編集

## ファイル構成

| ファイル | 役割 |
|---|---|
| `Code.gs` | サーバーサイド一式(シート初期化、CRUD API) |
| `Index.html` | メイン画面のHTML(テンプレート) |
| `Stylesheet.html` | CSS(`<?!= include('Stylesheet'); ?>` で読み込み) |
| `JavaScript.html` | フロントJS(同上) |
| `appsscript.json` | マニフェスト(タイムゾーン、Web App設定) |

| SubjectID | 科目名 | 表示順 | 試験日 |
|---|---|---|---|
| S_xxxxxxxx | 数学 | 1 | 2026-07-15(空欄可) |

## 初回セットアップ手順

### 1. GASプロジェクトを作成する

どちらの方法でもOKです。

**方法A:スプレッドシートにひも付けて作る(おすすめ)**
1. [Googleスプレッドシート](https://sheets.new)で新規シートを作成(名前は自由。例:「テスト勉強進捗管理」)
2. メニューの「拡張機能」→「Apps Script」を開く

**方法B:スタンドアロンで作る**
1. [script.new](https://script.new) で新規GASプロジェクトを作成
2. この場合、初回アクセス時に「テスト勉強進捗管理データ」というスプレッドシートが自動作成されます(IDはスクリプトプロパティに保存され、以後使い回されます)

### 2. ファイルを貼り付ける

Apps Scriptエディタで以下の4ファイルを作成し、このリポジトリの内容をそのまま貼り付けます。

1. 既存の `コード.gs` の中身を `Code.gs` の内容に置き換える
2. 「＋」→「HTML」で **Index** を作成 → `Index.html` の内容を貼り付け
3. 同様に **Stylesheet** を作成 → `Stylesheet.html` の内容を貼り付け
4. 同様に **JavaScript** を作成 → `JavaScript.html` の内容を貼り付け

※ HTMLファイル名は `Index` / `Stylesheet` / `JavaScript` と正確に一致させてください(`include()` で参照しているため)。

(任意)エディタの「プロジェクトの設定」→「『appsscript.json』マニフェストファイルをエディタで表示する」を有効にすると、`appsscript.json` も貼り付けられます(タイムゾーンをAsia/Tokyoに固定)。

### 3. Web Appとしてデプロイする

1. エディタ右上の「デプロイ」→「新しいデプロイ」
2. 種類の選択(歯車アイコン)で「**ウェブアプリ**」を選ぶ
3. 設定:
   - 説明:任意(例:v1)
   - 次のユーザーとして実行:「**自分**」
   - アクセスできるユーザー:「**自分のみ**」(個人利用のため)
4. 「デプロイ」を押し、承認を求められたらアカウントを選んで許可する
   (「このアプリはGoogleで確認されていません」と出た場合は「詳細」→「(プロジェクト名)に移動」で続行)
5. 発行された **ウェブアプリのURL** を開く。初回アクセス時にシート(Subjects / Tasks)が自動作成されます

スマホからも同じURLでアクセスできます(同じGoogleアカウントでログインしていること)。ホーム画面に追加しておくとアプリのように使えます。

### 4. コードを更新したとき

「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →バージョンを「**新バージョン**」にして「デプロイ」すると、**URLを変えずに**最新コードが反映されます(「新しいデプロイ」を作るとURLが変わるので注意)。

## サーバーAPI一覧

| 関数 | 内容 |
|---|---|
| `getDashboardData()` | 科目・タスク・今日の日付をまとめて取得 |
| `addSubject(name, examDate)` | 科目を追加(表示順は末尾) |
| `updateSubjectExamDate(subjectId, examDate)` | 試験日を変更(空文字で解除) |
| `updateSubjectName(subjectId, name)` | 科目名を変更 |
| `deleteSubject(subjectId)` | 科目を削除(属するタスクも削除) |
| `addTask(subjectId, name, dueDate)` | タスクを追加 |
| `updateTaskProgress(taskId, progress)` | 進捗率を更新(0〜100に丸め) |
| `updateTaskMemo(taskId, memo)` | メモを更新 |
| `updateTaskDueDate(taskId, dueDate)` | 期限日を更新 |
| `deleteTask(taskId)` | タスクを削除 |

書き込み系はすべて `LockService` で排他制御しています。

## 拡張のポイント

- **新しいデータ種別**(勉強時間ログなど):`Code.gs` の `SHEET_DEFS` に定義を追加し、対応するAPI関数を増やすだけでシートは自動作成されます
- **通知機能**:GASの時間主導トリガー + `MailApp` / LINE Notify 等で、`getDashboardData()` の結果から期限アラートを定期送信できます
- 日付はすべて `'yyyy-MM-dd'` の文字列でやり取りしているため、クライアント/サーバー間のタイムゾーンずれが起きにくい構造です
