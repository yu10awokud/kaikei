# 部費立替メモ

KPUM水泳部の練習ごとに発生した立替を、**領収書の写真つきで記録・集計する**ための小さなWebアプリです。

既存サイト「メニュー特戦隊」（https://kpumswimmenu.vercel.app ）とは**別のアプリ**として動きます。
既存サイトのコードもデータも、このアプリは一切書き換えません。

---

## このアプリの仕組み（ざっくり）

```
   既存サイトの練習カレンダー              このアプリ
  ┌────────────────────┐        ┌──────────────────────┐
  │ assignments（練習日）│  読む  │ 練習一覧              │
  │ places（練習場所）   │ ─────→ │  日付＋練習場所だけ表示 │
  └────────────────────┘        │                      │
        ※ 書き込みは一切しない      │ 立替入力・一覧・集計    │
                                 └──────────┬───────────┘
                                            │ 書く
                                 ┌──────────▼───────────┐
                                 │ expenses（立替の記録） │
                                 │ receipts（領収書の画像）│
                                 └──────────────────────┘
```

**大事な点：練習の予定はこのアプリの中にコピーしません。** 画面を開くたびに既存サイトと
同じデータベースを見に行きます。そのため、既存サイト側で練習場所を変えれば、こちらにも
そのまま反映されます。二重管理になりません。

なお、表示するのは**日付と練習場所だけ**です。メニュー担当者は取得もしていません。

---

## セットアップ手順

プログラミングに詳しくなくても進められるよう、1つずつ書いてあります。
**上から順に、飛ばさずに進めてください。**

### 手順1：Supabase に立替用のテーブルを作る

既存サイトと**同じ** Supabase プロジェクトに、新しいテーブルを1つ足します。
既存のテーブル（members / places / assignments など）は変更しません。

1. ブラウザで https://supabase.com/dashboard を開き、ログインします。
2. 既存サイトで使っているプロジェクトをクリックします。
3. 左側のメニューから **「SQL Editor」** をクリックします。
4. 画面右上の **「New query」** をクリックします。
5. このフォルダの中の **`supabase/migration-expenses.sql`** をテキストエディタで開き、
   **中身をすべてコピー**して、SQL Editor の入力欄に貼り付けます。
6. 右下の **「Run」** ボタンを押します。
7. 画面下に `Success. No rows returned` と出れば成功です。

> この SQL は何度実行しても壊れません。うまくいったか不安なときは、もう一度 Run しても大丈夫です。

これで次の2つができます。
- `expenses` テーブル（立替の記録を入れる場所）
- `receipts` バケット（領収書の画像を入れる場所。**非公開**設定）

### 手順2：Supabase のキーを控える

1. 同じプロジェクトの画面で、左下の **「Project Settings」**（歯車のアイコン）をクリックします。
2. **「API」** をクリックします。
3. 次の2つをメモ帳などにコピーしておきます。
   - **Project URL**（`https://〇〇〇.supabase.co` という形）
   - **service_role** の key（`Project API keys` の欄にあります。`Reveal` を押すと見えます）

> **service_role の key は、部の全データを操作できる「マスターキー」です。**
> LINE やメールで人に送ったり、GitHub に貼り付けたりは絶対にしないでください。

### 手順3：パソコンで動かしてみる（任意）

いきなり公開してもよいのですが、手元で試したい場合の手順です。

1. このフォルダ（`expense-app`）で、ターミナルを開きます。
2. `.env.example` をコピーして `.env.local` という名前のファイルを作ります。

   ```bash
   cp .env.example .env.local
   ```

3. `.env.local` をテキストエディタで開き、手順2で控えた値を `=` の右側に貼り付けます。

   ```
   NEXT_PUBLIC_SUPABASE_URL=https://〇〇〇.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=（service_role の key）
   ```

4. 必要な部品をインストールして、起動します。

   ```bash
   npm install
   npm run dev
   ```

5. ブラウザで http://localhost:3000 を開きます。練習一覧が出れば成功です。

> `.env.local` は `.gitignore` で除外してあるので、GitHub には上がりません。

### 手順4：Vercel に新しいプロジェクトとして公開する

**既存サイトの Vercel プロジェクトは触りません。新しくもう1つ作ります。**

1. https://vercel.com/new を開きます。
2. リポジトリの一覧から **`yu10awokud/kaikei`** を選び、**Import** をクリックします。
   （既存サイトと同じリポジトリですが、次の手順で見る場所を変えるので問題ありません）
3. **★ここが一番大事です。** `Root Directory` の欄の **Edit** を押し、
   **`expense-app`** を選びます。
   ここを変えないと、既存サイトの方がもう一度公開されてしまいます。
4. `Environment Variables` を開き、次の2つを追加します。

   | Name | Value |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | 手順2の Project URL |
   | `SUPABASE_SERVICE_ROLE_KEY` | 手順2の service_role の key |

5. **Deploy** を押します。数分待つと、新しい URL（`〇〇〇.vercel.app`）ができます。

これで完成です。

## 使い方

### 練習タブ

既存カレンダーから読み取った練習が、日付と練習場所で並びます。
「オフ」の日は立替の対象にならないので表示しません。

各行の **「立替を記録する」** から入力に進みます。

### 立替の入力

| 項目 | 説明 |
|---|---|
| 立て替えた人 | 部員マスタから選びます。マスタに無い人は「その他」で名前を入力できます |
| 金額 | 円。1円単位の整数で入力します |
| 項目 | 部費立替 / プリペイド立替 / 後援会費立替 / その他（内容を自由入力） |
| 返金の有無 | **必要** … 立て替えた人にお金を返す（未精算として集計）<br>**不要** … 部のお金からそのまま払った（未精算に入れない） |
| メモ | 任意。「メニュー印刷代」など |
| 領収書 | 「カメラで撮影」か「ライブラリから選ぶ」。スマホならその場で撮れます |

**入力例1**：9/1 に冨士原さんがメニュー印刷代を80円立て替えた
→ 金額 `80` ／ 項目 `部費立替` ／ 返金の有無 `必要`

**入力例2**：9/3 に奥田さんがプール代 10,800円 を支払った
→ 金額 `10800` ／ 項目 `プリペイド立替` ／ 返金の有無 `不要`

領収書の写真は、送る前にブラウザ側で**長辺1600px・JPEG**に縮小します。
スマホの写真がそのまま上がって重くなることはありません。

### 立替一覧タブ

立て替えた人と精算状況で絞り込めます。領収書はサムネイルで並び、タップすると拡大します。
返金が必要なものは **「精算済みにする」** で消し込みできます。

「取り消す」を押しても、データは消えずに隠れるだけです（論理削除）。
間違えて消しても、Supabase の画面から `is_deleted` を `false` に戻せば復活します。

### 集計タブ

期間を指定して、部員ごとの立替合計と未精算合計、項目ごとの合計を出します。
**CSV でダウンロード**できます。Excel でそのまま開けます（文字化けしません）。

## 安全面について

- **領収書は非公開の保存場所**に入れています。URL を知っていても、そのままでは開けません。
  画面に出すときだけ、30分で切れる一時的な URL をサーバーが発行します。
- `expenses` テーブルは、ブラウザに渡る公開キーからは**読むことも書くこともできません**。
  読み書きはすべてサーバー側（`app/api/...`）が秘密キーで行います。
- 秘密のキーはコードには一切書かれていません。`.env.local` と Vercel の設定画面だけに入ります。
- **ログイン機能はありません。** URL を知っている人は操作できてしまうので、
  **この URL は人に共有しないでください。** 後から合言葉での入室を足すこともできます。

## ファイルの置き場所

```
expense-app/
├─ app/
│  ├─ page.tsx              練習一覧のページ
│  ├─ expenses/page.tsx     立替一覧のページ
│  ├─ summary/page.tsx      集計のページ
│  └─ api/                  サーバー側の処理（秘密キーを使うのはここだけ）
│     ├─ practices/         既存カレンダーを読む
│     ├─ members/           部員マスタを読む
│     ├─ expenses/          立替の登録・一覧・更新・CSV
│     └─ receipts/          領収書の保存と、表示用の一時URL発行
├─ components/              画面の部品
├─ lib/                     共通の処理（金額の検証・画像の縮小など）
└─ supabase/
   └─ migration-expenses.sql   手順1で実行する SQL
```

## よくあるつまずき

| 画面に出るメッセージ | 対処 |
|---|---|
| Supabase の環境変数が設定されていません | `.env.local`（または Vercel の Environment Variables）に2つの値が入っているか確認してください |
| expenses テーブルがまだ作られていません | 手順1の SQL を実行してください |
| 領収書の保存先（receipts バケット）が見つかりません | 手順1の SQL を実行してください |
| Supabase のキーが正しくありません | `service_role` の key を貼り間違えていないか確認してください（`anon` の方ではありません） |
| 接続先URLが正しくありません | `https://〇〇〇.supabase.co` の形か、末尾に余計な `/` が付いていないか確認してください |

うまく読み込めなかったときは、画面に **「再読み込みする」** ボタンが出ます。
真っ白になることはありません。
