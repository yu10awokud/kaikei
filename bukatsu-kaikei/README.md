# 部活動 会計管理ツール（GAS Webアプリ）

プール（施設）ごとに1人あたり料金が異なる部活の、**プリペイド式（チャージ→都度差引）会計**を
スマホからアプリのように管理するためのGoogle Apps Script製ツールです。会計担当者専用。

## できること

| 機能 | 内容 |
|---|---|
| ① 練習日の設定 | 練習日ごとに「使用プール」を設定 |
| ② 出席記録 | その日の出席部員をタップで記録 |
| ③ 精算 | 出席者全員のプリペイド残高から、使用プールの1人あたり料金を自動で差引 |
| ④ チャージ | 誰が・いつ・いくら入金したかを記録し残高に反映 |
| ⑤ 残高ランキング | 上位3名＝富豪 / 下位3名＝借金、全員の残高一覧 |
| ⑥ 出席ランキング | 月ごとの出席回数ランキング（練習日数も表示） |
| ⑦ イベント会計 | 新歓コンパ・追いコン等。参加者（原則全員・当欠者は個別に外せる）の残高から1人あたり金額を差引 |
| ⑧ 外部参加記録 | 他大学選手などの立替台帳。日付・氏名・所属・プール・金額・決済手段・回収状況を記録（残高とは独立） |
| ⑨ 残高PDF発行 | 全部員の残高カードを学年ごとに色分けした1枚のPDFを発行（月末共有用） |

## 設計方針（重要）

- **残高は保存しない**：残高は常に `Σチャージ − Σ支払い` で計算します。マスタに残高列を持たないため、
  記録の修正・削除をしても整合性がズレません（チャージ履歴と支払い履歴が唯一の正データ）。
- **料金は精算時点で焼き込む**：支払い履歴には精算した時の料金を実額で保存します。後からプール代マスタを
  変更しても、過去の精算額は変わりません。
- **精算は二重実行できない**：練習日ごとに「精算済フラグ」を持ち、二重差引を防ぎます。修正したい場合は
  「精算を取り消す」で元に戻してから再操作します。
- **引退／現役はラベルのみ**：集計・ランキングは全部員を同じ扱いにします（引退部員も練習参加を想定）。
- **マネ（マネージャー）はプール代の差引対象外**：出席は記録され出席ランキングには計上されますが、
  精算時にプリペイド残高から料金は引かれません（区分＝`マネ`で判定）。
  - **例外：プールごとに「マネも徴収」を設定可能**。プール代マスタで対象プール（例：アクオン）の
    「マネも徴収」にチェックを入れると、そのプールの日はマネさんからも料金を差し引きます。

## シート構成（初回アクセス時に自動生成）

| シート | 列 |
|---|---|
| `部員マスタ` | 部員ID・氏名・学年・学科・区分(プレ/マネ)・状態(現役/引退) |
| `プール代マスタ` | プール名・料金（1人あたり）・マネも徴収（TRUE/FALSE） |
| `練習日程` | 日付・使用プール・精算済 |
| `出席記録` | ID・日付・部員ID・出席 |
| `入金記録` | ID・日付・部員ID・金額・メモ |
| `支払い履歴` | ID・日付・部員ID・プール名（イベント名）・金額・元（出所） |
| `外部参加記録` | ID・日付・氏名・所属・使用プール・金額・決済手段・状態・メモ |
| `イベント` | ID・日付・イベント名・用途・金額（1人あたり）・精算済 |
| `イベント参加` | ID・イベントID・部員ID |

> `支払い履歴`の「元」列は、精算取り消しを練習/イベントで取り違えないための出所キー
> （`practice:日付` / `event:イベントID`）。既存シートには初回アクセス時に自動で追加されます。
> イベント精算も残高に反映させるため、支払い履歴に統合して記録します（プリペイド＝共通の財布）。

## 使い方の流れ

1. **マスタ**タブで部員とプール（料金）を登録する
2. **練習日**タブで日付を選び、使用プールを「設定」→ 出席者をタップ →「出席を保存」
3. 同じ画面で「この日を精算する」を押すと、出席者全員の残高から料金が引かれる
4. **チャージ**タブで入金を記録する
5. **残高**タブで残高一覧・富豪/借金ランキングを確認（月初のスクショ共有はここを撮る）
6. **出席ランキング**タブで月ごとの出席状況を確認

> 上部の `‹ / ›` で対象月を切り替えます（残高ランキング・チャージ・出席ランキングが月に連動）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `Code.gs` | サーバー側。シート読み書き・残高計算・精算ロジック |
| `Index.html` | 画面構造（残高／練習日／チャージ／出席ランキング／マスタ） |
| `Stylesheet.html` | デザイン（CSS） |
| `JavaScript.html` | 画面の動き（クライアント側JS） |
| `appsscript.json` | GAS設定（タイムゾーン・Webアプリ設定） |

## セットアップ

1. [Googleスプレッドシート](https://sheets.google.com)を新規作成
2. **拡張機能 → Apps Script** でエディタを開く
3. 下記5ファイルを作成し、このフォルダの中身をそのまま貼り付け
   - `Code.gs`（既存の`コード.gs`を置き換え）
   - `Index` / `Stylesheet` / `JavaScript`（「＋」→ HTML、拡張子なしの名前で作成）
   - `appsscript.json`（⚙️設定 → マニフェストを表示 にチェックして貼り付け）
4. 関数 `init` を一度実行して承認 → シートが自動生成される
   - **PDF発行機能を使うため、Google Drive／外部リクエストへのアクセス許可が新たに求められます**。
     `init` 実行時の権限確認で許可してください（既存プロジェクトを更新した場合も、一度 `init` を実行して再承認が必要）。
   - PDFは一時シートに描画→スプレッドシートのPDFエクスポート機能で出力しています（セル背景色を
     確実に反映させるため）。GASのHTML→PDF変換は背景色を描画できないため、この方式を採用しています。
5. **デプロイ → 新しいデプロイ → ウェブアプリ**（実行:自分 / アクセス:自分のみ）→ 発行URLをブックマーク

コードを修正したら **デプロイ → デプロイを管理 → 編集 → 新バージョン → デプロイ**（URLは不変）。

## 計算ルール

- 各部員の残高 = `その部員のチャージ合計` − `その部員の支払い合計`
- 1回の精算 = `使用プールの1人あたり料金` × `その日の出席者数（マネを除く）`（対象者それぞれから同額を差引）
- 割り勘（使用料÷人数）ではなく、**プールごとに固定された1人あたり料金**を引く方式です
